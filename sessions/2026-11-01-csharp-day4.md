# Topic 1: Generics in C#

## 1. The problem generics solve

Imagine you're implementing a reusable storage class.

You want to store integers:

```csharp
public class IntStorage
{
    private int value;

    public void Set(int value)
    {
        this.value = value;
    }

    public int Get()
    {
        return value;
    }
}
```

Now suppose you also need storage for strings.

You might create another class:

```csharp
public class StringStorage
{
    private string value;

    public void Set(string value)
    {
        this.value = value;
    }

    public string Get()
    {
        return value;
    }
}
```

And then another for `Employee`, another for `Order`, and so on.

This creates code duplication.

Could we instead write one class that works with different data types while retaining compile-time type safety?

That's exactly what **generics** provide.

## 2. Introducing generic classes

```csharp
public class Storage<T>
{
    private T value;

    public void Set(T value)
    {
        this.value = value;
    }

    public T Get()
    {
        return value;
    }
}
```

Here, `T` is a type parameter.

When creating an object, we specify the actual type:

```csharp
Storage<int> intStorage = new Storage<int>();
intStorage.Set(100);

int result = intStorage.Get();
```

For strings:

```csharp
Storage<string> stringStorage = new Storage<string>();
stringStorage.Set("Hello");

string result = stringStorage.Get();
```

The compiler ensures that the type is consistent.

For example:

```csharp
Storage<int> storage = new Storage<int>();

storage.Set(100);       // Valid
storage.Set("Hello");   // Compile-time error
```


  **How to think about `Storage<T>`**


    **Storage<T>**

    Generic class definition



      **Storage<int>**
      T = int
      Stores integers


      **Storage<string>**
      T = string
      Stores strings


  One generic definition, different strongly typed constructions.


## 3. Why not just use `object`?

You might wonder why we need generics when C# already has `object`, the base type of all .NET types.

Consider:

```csharp
public class ObjectStorage
{
    private object value;

    public void Set(object value)
    {
        this.value = value;
    }

    public object Get()
    {
        return value;
    }
}
```

Using it:

```csharp
ObjectStorage storage = new ObjectStorage();

storage.Set(100);

int result = (int)storage.Get();
```

There are two problems:

1. We need explicit casting when retrieving the value.
2. We lose compile-time type safety.

For example:

```csharp
storage.Set("Hello");

int result = (int)storage.Get(); // Runtime exception
```

With generics, this incorrect assignment is caught at compile time.

Generics also avoid boxing and unboxing in common value-type scenarios, unlike storing value types as `object`.

## 4. Generic methods

Generics aren't limited to classes. Individual methods can also be generic.

```csharp
public static T GetFirst<T>(T[] items)
{
    return items[0];
}
```

Usage:

```csharp
int number = GetFirst(new[] { 10, 20, 30 });

string name = GetFirst(new[] { "A", "B", "C" });
```

The compiler can infer `T` from the method argument, so explicitly specifying it isn't always necessary.
